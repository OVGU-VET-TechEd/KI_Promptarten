Prompt-Arten verstehen

Vom Chat zum lernenden KI-Agenten in vier Stufen: Was steckt hinter Interaktions-, System-, Skill-, Harness-, Loop- und Wiki-Prompts? Und warum ist das, was Sie eintippen, nur ein kleiner Teil dessen, was das Sprachmodell tatsächlich „liest“?

1 · Das große Bild

Ein Sprachmodell hat kein Gedächtnis und keine Hände. Es bekommt bei jeder Antwort einen großen Textblock – das Kontextfenster – und schreibt den wahrscheinlichsten Text dazu. Die sechs Prompt-Arten beschreiben, wer welchen Teil dieses Textblocks schreibt und wann er hineinkommt.

Der rote Faden: vier Stufen

Jede Stufe baut auf der vorherigen auf. In dieser Reihenfolge ist die ganze Seite aufgebaut: Tabs, Simulation, Vergleich und Übungen.

  1. Stufe 1Mit dem Modell sprechenWas Sie schreiben und welche Regeln immer gelten.
    🗣️ Interaktion📋 System
  2. Stufe 2Harness: Einfluss ausbauenDie Software um das Modell lädt Arbeitsanweisungen nach und gibt ihm Werkzeuge.
    📚 Skill🏭 Harness
  3. Stufe 3Loops: Grenzen prüfenDer Agent arbeitet in Runden, mit Prüfkriterien, Abbruchregel und Übergabe an einen Menschen.
    🔁 Loop
  4. Stufe 4Lernende AgentenWas der Agent einmal geklärt hat, schreibt er ins Wiki und nutzt es beim nächsten Mal.
    📓 Wiki

Stellen Sie sich das Modell als neue Auszubildende vor: sehr belesen, aber mit zwei Schwächen. Sie vergisst über Nacht alles, und sie kann ohne Werkstatt nichts anfassen. Damit sie trotzdem gute Arbeit macht, braucht sie zuerst einen Auftrag und Betriebsregeln (Stufe 1), dann Arbeitsanweisungen und eine Werkstatt (Stufe 2), eine Qualitätsprüfung mit klaren Grenzen (Stufe 3) und schließlich ein Berichtsheft, aus dem sie lernt (Stufe 4). Genau das sind die sechs Prompt-Arten.

2 · Die sechs Prompt-Arten im Detail

Stufe 1 · Mit dem Modell sprechen

Der Interaktionsprompt ist die Nachricht, die Sie selbst in das Chatfenster tippen: ein konkreter Auftrag für genau diesen Moment.

Wer schreibt ihn?Sie als Nutzer:in
Wann wirkt er?für die aktuelle Antwort (bleibt im Verlauf)
Sichtbar?ja, für Sie
Andere NamenUser-Prompt, Eingabe, Anfrage
🗣️
In der Werkstatt: der mündliche Arbeitsauftrag der Meisterin: „Bau bitte die Reihenschaltung auf Platz 3 auf.“
Beispiel
Erstelle 5 Quizfragen zum Thema Schutzleiter für Elektroniker:innen
im 1. Ausbildungsjahr. Format: Multiple Choice, eine richtige Antwort.

Gute Interaktionsprompts enthalten Rolle · Aufgabe · Kontext · Format · Beispiele (Sie kennen das aus der KI-Einführung). Aber: Ein Interaktionsprompt allein muss alles mitbringen. Was nicht drinsteht, muss das Modell raten.

Technisch ist der Interaktionsprompt eine Nachricht mit der Rolle user. Sprachmodelle sind zustandslos: Bei jeder neuen Nachricht schickt die App den gesamten bisherigen Verlauf erneut mit. Ein „Gedächtnis“ im Chat entsteht nur dadurch.

POST /api/chat
{
  "model": "gemma4:e2b",
  "messages": [
    { "role": "user",      "content": "Was ist ein Schutzleiter?" },
    { "role": "assistant", "content": "Ein Schutzleiter ist …" },
    { "role": "user",      "content": "Und warum ist er grün-gelb?" }   ← neuer Interaktionsprompt
  ]
}

Folge: Lange Chats füllen das Kontextfenster. Irgendwann wird gekürzt oder zusammengefasst, und frühe Details gehen verloren.

Typischer Fehler: „Mach mal ein Arbeitsblatt.“ Ohne Zielgruppe, Thema und Format wird die Antwort beliebig.

Stufe 1 · Mit dem Modell sprechen

Der Systemprompt steht vor dem ganzen Gespräch. Er legt fest, wer das Modell sein soll, wie es antwortet und welche Regeln immer gelten.

Wer schreibt ihn?Anbieter der App, Lehrende, Entwickler:innen, teils Sie selbst („Eigene Anweisungen“)
Wann wirkt er?bei jeder Antwort der Sitzung
Sichtbar?meist nicht
Andere NamenSystemnachricht, Custom Instructions, Persona
📋
In der Werkstatt: Ausbildungsvertrag und Betriebsordnung. Sie gelten jeden Tag, ohne dass die Meisterin sie bei jedem Auftrag wiederholt.
Beispiel
Du bist ein Lernbegleiter für Auszubildende in gewerblich-technischen Berufen.
- Antworte auf Deutsch in einfacher Sprache (B1), höchstens 6 Stichpunkte.
- Verweise bei Arbeitsschutz immer auf die Prüfung durch die Lehrkraft.
- Wenn du unsicher bist, sag es.

Jede Chat-App hat einen Systemprompt, auch wenn Sie ihn nie sehen. Er erklärt, warum dieselbe Frage in zwei Apps unterschiedlich beantwortet wird. Wenn Sie für Ihre Lernenden einen eigenen KI-Assistenten einrichten, schreiben Sie den Systemprompt.

Rolle system, immer an erster Stelle der Nachrichtenliste. Modelle sind darauf trainiert, System-Anweisungen höher zu gewichten als Nutzernachrichten (Instruction Hierarchy). Das ist aber kein sicherer Schutz: Mit Prompt-Injection („Ignoriere alle vorherigen Anweisungen …“) wird versucht, ihn auszuhebeln.

[
  { "role": "system", "content": "Du bist ein Lernbegleiter … (Regeln)" },
  { "role": "user",   "content": "Wie gehe ich sicher mit einem Lötkolben um?" }
]

Im Starter-Kit: 02_systemprompt.py stellt dieselbe Frage ohne und mit Systemprompt.

Typischer Fehler: Ein Systemprompt mit 80 Regeln. Je länger und widersprüchlicher, desto eher werden einzelne Regeln übersehen.

Stufe 2 · Harness: Einfluss ausbauen

Ein Skillprompt ist eine abgelegte Anleitung für eine bestimmte Aufgabe. Das Modell kennt zunächst nur Titel und Kurzbeschreibung aller Skills, und die Harness lädt die vollständige Anleitung erst, wenn sie gebraucht wird.

Wer schreibt ihn?Fachleute, Lehrende, Teams: einmal, für viele Anwendungen
Wann wirkt er?nur wenn die Aufgabe passt
Sichtbar?als Datei/Ordner: ja
Andere NamenAgent Skill, Fähigkeit, Arbeitsanweisung
📚
In der Werkstatt: das Regal mit Arbeitsanweisungen. Auf jedem Ordnerrücken steht, wofür er ist („Gefährdungsbeurteilung“, „Lötstelle prüfen“). Aufgeschlagen wird nur der Ordner, der gerade gebraucht wird.
Beispiel: Ordner gefaehrdungsbeurteilung/SKILL.md
---
name: gefaehrdungsbeurteilung
description: Erstellt eine kurze Gefährdungsbeurteilung für einen Laboraufbau.
             Nutzen, wenn nach Gefährdungen oder Schutzmaßnahmen gefragt wird.
---
1. Tabelle: Gefährdung | Ursache | Schutzmaßnahme (T-O-P) | Rechtsgrundlage
2. Rechtsgrundlagen nur nennen, wenn sicher, sonst „bitte prüfen“.
3. Schlusssatz: „KI-Entwurf, muss fachkundig geprüft werden.“

Der Unterschied zum Systemprompt: Ein Systemprompt gilt immer. Ein Skill ist Spezialwissen auf Abruf. So kann ein Assistent hunderte Skills haben, ohne dass sein Kontextfenster überläuft.

Prinzip Progressive Disclosure (schrittweises Aufdecken):

  1. Im Kontext steht nur der Katalog: name + description aus dem YAML-Kopf jeder SKILL.md (wenige Dutzend Token pro Skill).
  2. Passt eine Aufgabe, lädt der Agent den Inhalt der SKILL.md.
  3. Bei Bedarf liest er weitere Dateien im Skill-Ordner (Vorlagen, Beispiele, Skripte).

Das Format „Agent Skills“ (Ordner mit SKILL.md) wird von mehreren Agenten-Werkzeugen unterstützt, z. B. Claude, GitHub Copilot in VS Code oder OpenAI Codex. Entscheidend für die Auswahl ist die description: Sie sagt, wann der Skill genutzt werden soll.

Im Starter-Kit: 03_skillprompt.py zeigt beide Schritte, Katalog und Nachladen, farbig im Terminal.

Typischer Fehler: Eine vage Beschreibung („Hilft bei Dokumenten“). Dann wird der Skill nie oder zur falschen Zeit gewählt.

Stufe 2 · Harness: Einfluss ausbauen

Die Harness ist die Software um das Sprachmodell herum. Mit ihr wachsen die Möglichkeiten, das Modell zu steuern: Sie baut Systemprompt und Skills in den Kontext ein, gibt ihm Werkzeuge und setzt Berechtigungen. Der Harness-Prompt ist der Text, mit dem sie dem Modell erklärt, was es tun darf, was es gerade „sieht“ und wie es Werkzeuge anfordert.

Wer schreibt ihn?Hersteller der Agenten-Software
Wann wirkt er?während der ganzen Arbeit des Agenten
Sichtbar?nein, er wird automatisch zusammengesetzt
BeispieleClaude Code, GitHub Copilot (Agent-Modus), Cursor, Cline
🏭
In der Werkstatt: die Werkstatt selbst, mit Werkbank, Werkzeugschrank, Not-Aus und Zugangsregeln. Ohne Werkstatt kann die Auszubildende nur erklären, wie man lötet. In der Werkstatt kann sie es tun, aber nur mit den Werkzeugen, die dort liegen, und nur in ihrem Bereich.

Wichtig: Das Modell selbst kann nur Text schreiben. Wenn es „eine Datei speichert“, schreibt es eigentlich: „Bitte Werkzeug schreibe_datei mit Inhalt X“. Die Harness führt das aus, prüft die Berechtigung und meldet das Ergebnis zurück. Das wiederholt sich, bis die Aufgabe erledigt ist.

Beispiel: Ausschnitt eines Harness-Prompts
Du arbeitest in einer Arbeitsumgebung. Heutiges Datum: 27.10.2026.
Dein Arbeitsordner enthält: laborauftrag.txt
Verfügbare Werkzeuge:
- lies_datei {"name": …}        – liest eine Datei
- schreibe_datei {"name": …, "inhalt": …}
- fertig {"zusammenfassung": …}
Regeln: Lies Dateien, bevor du über sie schreibst. Nur im Arbeitsordner arbeiten.

Eine Harness besteht typischerweise aus: Werkzeugdefinitionen (Name, Beschreibung, JSON-Schema der Argumente) · Umgebungsinfos (Datum, Betriebssystem, Ordner) · Verhaltensregeln · Berechtigungssystem (Was darf ohne Rückfrage passieren?) · Kontextverwaltung (Verlauf kürzen, Dateien nachladen) · der Agentenschleife:

nachrichten = [harness_prompt, aufgabe]
while schritte < MAX:
    antwort = modell(nachrichten)            # Modell schlägt Aktion vor
    if antwort.werkzeug == "fertig": break
    if not erlaubt(antwort): frage_nutzer()  # Harness setzt Grenzen
    ergebnis = fuehre_aus(antwort.werkzeug)  # Harness handelt
    nachrichten += [antwort, ergebnis]       # Ergebnis zurück ins Kontextfenster

Systemprompt, Skill-Katalog und Projektdateien werden von der Harness in den Kontext eingebaut. Die Harness ist also der „Dirigent“ aller anderen Prompt-Arten. Kleine Modelle scheitern oft genau hier: falsche Werkzeugnamen, kaputtes JSON, Endlosschleifen.

Im Starter-Kit: 04_harness.py ist eine komplette Mini-Harness in ca. 100 Zeilen Python.

Merke: Je mehr Werkzeuge eine Harness freigibt (Dateien löschen, E-Mails senden), desto wichtiger sind Grenzen und menschliche Freigaben. Genau darum geht es in Stufe 3.

Stufe 3 · Loops: Grenzen prüfen

Ein Loop-Prompt ist ein Auftrag, der wiederholt ausgeführt wird: so lange, bis ein Prüfkriterium erfüllt ist, oder in festen Abständen. Er setzt dem Agenten Grenzen: Was gilt als fertig, wie viele Runden sind erlaubt, und wann übernimmt ein Mensch?

Wer schreibt ihn?Sie oder die Entwickler:innen eines Agenten
Wann wirkt er?in jeder Runde neu
KernbestandteileZiel · Prüfkriterien · Rückmeldung · Abbruchregel · Übergabe an Menschen
VerwandtPDCA-Zyklus, iteratives Prompting
📏
In der Werkstatt: Werkstück fertigen → messen → nachbessern → wieder messen, bis die Toleranz eingehalten ist. Und nach drei Fehlversuchen holt man die Meisterin.
Beispiel
Überarbeite das Arbeitsblatt, bis ALLE Kriterien erfüllt sind:
1. Überschrift in Zeile 1   2. genau 5 nummerierte Aufgaben
3. Abschnitt „Sicherheitshinweis“   4. höchstens 220 Wörter
Hier ist der aktuelle Stand: {stand}
Rückmeldung der letzten Prüfung: {rueckmeldung}
Höchstens 5 Runden. Danach an einen Menschen übergeben.

Sie kennen das Prinzip aus dem iterativen Prompting („Überarbeite …“). Beim Loop-Prompt ist die Wiederholung eingeplant: Die Kriterien stehen vorher fest, und es gibt eine Abbruchregel, damit die Schleife nicht endlos läuft. Erst die Harness aus Stufe 2 macht solche Schleifen ohne Ihr Zutun möglich. Deshalb braucht jeder Loop klare Grenzen: Der Agent soll Lücken melden, statt sie mit Erfundenem zu füllen.

Zwei Formen begegnen Ihnen in Agenten-Werkzeugen:

  • Ziel-Loop: Derselbe Prompt wird immer wieder gestartet, der Fortschritt steht in Dateien (z. B. eine To-do-Liste). Eine Prüfung entscheidet über das Ende, idealerweise automatisiert (Tests, Checkliste per Skript), nicht durch das Modell selbst. In der Entwickler-Community heißt das Muster auch „Ralph-Loop“.
  • Zeit-Loop: Ein Prompt läuft in Intervallen, z. B. „Prüfe alle 30 Minuten, ob neue Abgaben im Ordner liegen“ (in Claude Code etwa mit /loop).
# Ziel-Loop in der Shell (vereinfacht)
for runde in 1 2 3 4 5; do
  ollama run gemma4:e2b "$(cat LOOP_PROMPT.md) $(cat stand.md) $(cat rueckmeldung.txt)" > stand.md
  python pruefe.py stand.md > rueckmeldung.txt && break   # Prüfung bestanden → Ende
done

Im Starter-Kit: 05_loop.py, mit einer Python-Prüffunktion, die Sie selbst erweitern können.

Typischer Fehler: Das Modell prüft sich selbst („Ist dein Text gut? – Ja.“). Gute Loops prüfen mit einer unabhängigen Instanz: Checkliste, Programm oder Mensch.

Stufe 4 · Lernende Agenten

Ein Wiki-Prompt legt fest, wie ein KI-Agent eine dauerhafte Wissenssammlung aufbaut und pflegt: Markdown-Seiten, die über viele Sitzungen hinweg wachsen. Das Wiki ist das Langzeitgedächtnis, das dem Modell selbst fehlt. Damit wird aus dem Agenten ein lernender Agent: Was in einem Loop geklärt wurde, steht beim nächsten Auftrag schon bereit.

Wer schreibt ihn?Sie bzw. das Team, einmalig. Das Wiki selbst schreibt dann die KI mit.
Wann wirkt er?beim Einlesen neuer Quellen und beim Nachschlagen
Sichtbar?ja, das Wiki sind normale Dateien
VerwandtProjektdateien wie AGENTS.md, Memory, Wissensdatenbank
📓
In der Werkstatt: das Berichtsheft bzw. das Werkstatt-Wiki. Was heute gelernt wurde, wird ordentlich aufgeschrieben, und morgen liest man nach, statt alles neu zu erfragen.
Beispiel
Du pflegst das Wiki unseres Seminars.
- Eine Seite pro Begriff (z. B. top-prinzip.md).
- Aufbau: Titel · Definition in 1–2 Sätzen · Kernpunkte · Quelle.
- Verlinke verwandte Seiten so: [[sicherheitsunterweisung]].
- Aktualisiere nach jeder neuen Quelle das Inhaltsverzeichnis index.md.
- Schreibe nur, was in der Quelle steht.

Der Unterschied zum Skill: Ein Skill sagt, wie man eine Aufgabe erledigt (Verfahren). Ein Wiki speichert, was man über ein Thema weiß (Fakten, Begriffe, Entscheidungen). Und: Das Wiki wird von der KI selbst weitergeschrieben.

Das Muster wurde unter dem Namen „LLM-Wiki“ bekannt (eine Idee von Andrej Karpathy). Typischer Aufbau:

quellen/        ← Rohmaterial (PDFs, Notizen, Texte), wird nie verändert
wiki/           ← von der KI gepflegte Seiten + index.md
WIKI_PROMPT.md  ← die Regeln: Aufbau, Benennung, Verlinkung, Pflege

Wiki statt reiner Suche (RAG): Bei klassischer Dokumentensuche werden bei jeder Frage Textschnipsel aus den Rohquellen gesucht. Beim Wiki wird das Wissen einmal sauber verarbeitet, verknüpft und gepflegt, und Widersprüche fallen beim Einpflegen auf. Projektdateien wie AGENTS.md oder CLAUDE.md sind eine kleine Form davon: Agenten lesen sie bei jedem Start und ergänzen sie.

Im Starter-Kit: 06_wiki.py einlesen und 06_wiki.py frage "…".

Typischer Fehler: Das Wiki ungeprüft wachsen lassen. Auch hier kann die KI Fehler einschleusen, die dann „dauerhaft“ werden. Stichproben gegen die Quellen sind Pflicht.

Interaktion vs. System

Stellen Sie zuerst nur diese Frage in einem neuen Chat:

Wie gehe ich sicher mit einem Lötkolben um?

Öffnen Sie dann einen neuen Chat. Falls es ein Feld für „Anweisungen“ oder „Systemprompt“ gibt, fügen Sie dies dort ein, sonst als erste Nachricht:

Für dieses ganze Gespräch gilt: Du bist Lernbegleiter für Auszubildende im 1. Ausbildungsjahr Elektrotechnik. Antworte in einfacher Sprache, höchstens 6 Stichpunkte, und verweise bei Sicherheitsthemen auf die Prüfung durch die Lehrkraft. Antworte jetzt nur mit „Verstanden“.

Stellen Sie die Frage erneut. Was ist anders?

Einen Skill nutzen

Ein Skill ist eine Arbeitsanweisung, die Sie immer wieder verwenden. Speichern Sie diesen Text in einer eigenen Datei und fügen Sie ihn ein, wenn Sie ihn brauchen:

ARBEITSANWEISUNG „Gefährdungsbeurteilung“ – gilt für den folgenden Auftrag:
1. Tabelle mit Spalten: Gefährdung | Ursache | Schutzmaßnahme (T/O/P) | Rechtsgrundlage
2. Schutzmaßnahmen nach T-O-P ordnen (technisch vor organisatorisch vor persönlich).
3. Rechtsgrundlagen nur nennen, wenn du sicher bist, sonst „bitte prüfen“.
4. Schlusssatz: „KI-Entwurf – muss fachkundig geprüft werden.“

AUFTRAG: Erstelle eine Gefährdungsbeurteilung für «Ihren Laboraufbau».

Probieren Sie den Auftrag auch ohne die Anweisung. Was liefert der Skill zusätzlich?

Nachdenken über die Harness

Eine Harness können Sie im normalen Chat nicht nachbauen, denn dort kann die KI nur schreiben, nicht handeln. Überlegen Sie stattdessen:

  • Welche Werkzeuge bräuchte ein KI-Agent, der Ihnen bei der Vorbereitung eines Laborversuchs hilft?
  • Welche davon würden Sie ohne Rückfrage erlauben, welche nie?
  • Was sollte er tun, wenn er nach 10 Schritten nicht fertig ist? (Das führt direkt zur nächsten Übung.)

Neugierig geworden? Schalten Sie oben auf 🔧 Fortgeschritten: Dort gibt es ein Starter-Kit, mit dem Sie eine echte Mini-Harness laufen lassen.

Loop von Hand

Lassen Sie ein Arbeitsblatt erstellen. Schicken Sie dann diesen Prüfauftrag und wiederholen Sie ihn, bis alles erfüllt ist (höchstens 3-mal):

Prüfe dein letztes Arbeitsblatt Punkt für Punkt gegen diese Checkliste und schreibe zu jedem Punkt „erfüllt“ oder „nicht erfüllt“:
1. Überschrift vorhanden
2. genau 5 nummerierte Aufgaben
3. Abschnitt „Sicherheitshinweis“
4. höchstens 220 Wörter
Gib danach das vollständig überarbeitete Arbeitsblatt aus.

Zählen Sie selbst nach: Stimmt die Selbstprüfung des Modells? (Oft nicht! Deshalb prüfen gute Loops unabhängig.)

Ihr eigenes Kurs-Wiki

Legen Sie ein Dokument „Mein Kurs-Wiki“ an. Am Ende einer Chat-Sitzung:

Hier ist mein bisheriges Kurs-Wiki: «Wiki-Text einfügen oder „leer“»
Ergänze es um die wichtigsten Begriffe aus unserem heutigen Gespräch.
Regeln: ein Abschnitt pro Begriff, Definition in 1–2 Sätzen, 3 Kernpunkte, keine erfundenen Inhalte. Gib das vollständige Wiki aus.

Speichern Sie das Ergebnis. Fügen Sie das Wiki beim nächsten Mal zu Beginn ein. Jetzt „erinnert“ sich die KI.

Das Prompt-Labor Starter-Kit: sechs kleine Python-Experimente, eines pro Prompt-Art. Sie laufen mit einem Sprachmodell, das lokal auf Ihrem Laptop arbeitet (Ollama). Keine Cloud, keine Kosten, keine Daten verlassen den Rechner.

⬇ Starter-Kit herunterladen (.zip) Quellcode auf GitHub ansehen

Einrichtung (einmalig, ca. 20 Min.)

  1. Ollama installieren: ollama.com/download. Danach läuft es im Hintergrund.
  2. Modell laden im Terminal: 
    ollama pull gemma4:e2b
    Test: ollama run gemma4:e2b "Sag Hallo" (Beenden mit /bye)
  3. Python ≥ 3.10 installieren: python.org. Windows: Häkchen „Add Python to PATH“. Zusatzpakete sind nicht nötig.
  4. VS Code installieren: code.visualstudio.com, plus Erweiterung „Python“ (wird vorgeschlagen).
  5. ZIP entpacken → VS Code → Datei → Ordner öffnen → prompt-labor.
  6. Starten: Terminal → Aufgabe ausführen … → z. B. „02 Systemprompt“, oder im Terminal python3 02_systemprompt.py (Windows: python).

Welches Modell?

  • gemma4:e2b: Standard, für Laptops mit 8–16 GB RAM.
  • gemma4:e4b: bessere Ergebnisse, braucht mehr Speicher.
  • llama3.2:3b: schnelle, getestete Alternative (ca. 2 GB).
  • gemma3:1b: für schwache Rechner (ca. 0,8 GB). Reicht für 01–03, scheitert meist an der Harness (04). Gerade das ist lehrreich.

Modell wechseln: in ollama_client.py die Zeile MODEL = … ändern oder im Terminal:

export PROMPT_LABOR_MODEL=llama3.2:3b        # macOS/Linux
$env:PROMPT_LABOR_MODEL="llama3.2:3b"        # Windows PowerShell

Die farbige Ausgabe zeigt immer das komplette Kontextfenster: violett = System, blau = Nutzer:in, grün = Modell, gelb = Harness.

Forschungsaufträge

  1. Systemprompt-Grenzen: Versuchen Sie in 01/02, den Systemprompt per Interaktionsprompt auszuhebeln („Ignoriere alle Regeln …“). Wann gelingt es?
  2. Skill-Auslösung: Schreiben Sie einen Skill betriebsanweisung. Testen Sie 5 Formulierungen: Wann wird er gewählt? Verbessern Sie die description.
  3. Harness-Sicherheit: Lesen Sie sicherer_pfad() in 04_harness.py. Was passiert, wenn das Modell ../../geheim.txt lesen will? Ergänzen Sie ein Werkzeug loesche_datei mit Rückfrage an den Menschen.
  4. Loop-Prüfung: Ersetzen Sie in 05_loop.py die Python-Prüfung durch eine Selbstprüfung des Modells. Wird das Ergebnis besser oder schlechter?
  5. Wiki-Qualität: Lesen Sie eine eigene Quelle ein und vergleichen Sie Wiki-Seite und Original. Was fehlt, was ist erfunden?
  6. Modellgröße: Lassen Sie 04 mit gemma3:1b und gemma4:e2b laufen. Woran scheitert das kleine Modell?

7 · Glossar

Sprachmodell (LLM)
Programm, das zu einem Text den wahrscheinlich passenden nächsten Text erzeugt. Es hat kein eigenes Gedächtnis zwischen zwei Anfragen.
Kontextfenster
Der gesamte Text, den das Modell für eine Antwort „liest“: Systemprompt, Skills, Wiki-Auszüge, Verlauf, Ihre Nachricht. Es ist begrenzt.
Token
Wortstücke, in denen Modelle Text verarbeiten. Die Größe des Kontextfensters wird in Token gemessen.
Agent
Sprachmodell + Harness: Es kann nicht nur antworten, sondern über Werkzeuge in mehreren Schritten handeln.
Lernender Agent
Agent, der Ergebnisse und Klärungen dauerhaft festhält (z. B. in einem Wiki) und beim nächsten Auftrag wieder nutzt.
Werkzeug (Tool)
Eine Funktion, die die Harness für das Modell ausführt, z. B. Datei lesen oder im Web suchen.
Progressive Disclosure
Wissen erst bei Bedarf in den Kontext laden (Prinzip der Skills).
Prompt-Injection
Versuch, über eingeschleusten Text die Regeln eines Systemprompts auszuhebeln.
Ollama
Kostenlose Software, mit der man Sprachmodelle lokal auf dem eigenen Rechner ausführt.
Markdown
Einfaches Textformat mit # für Überschriften und - für Listen. Skills, Wikis und LiaScript nutzen es.
